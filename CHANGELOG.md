# Журнал изменений

## 2026-10-24 — уточнение модерации Analytic AI по разделу 6.5 ТЗ

- Уточнён системный prompt проверки изображений: перечислены категории из ТЗ (оружие, наркотики, NSFW, алкоголь/табак как главный предмет кадра, документы/персональные данные, крупные планы лиц третьих лиц, водяные знаки и логотипы других площадок, контрафакт и запрещённая деятельность).
- Убрана субъективная проверка различий стиля/планировки между фото как самостоятельная причина модерации; сомнительные случаи остаются на ручной проверке.
- Обновлена инструкция Analytic AI с перечнем правил.
- Локальный тестовый запуск закреплён за доступной моделью Gemini 3.8 Flash, чтобы переменная окружения с другим названием модели не перенаправляла тест.
- Добавлены сценарии проверки всех пяти тестовых фотографий, статусов документов tax certificate/passport, независимого правила Listing `on_moderation/deep` и порога риска ровно в 5 баллов; в тестовые результаты выводятся фактические red flags и баллы по ТЗ.
- Запретил модели следовать текстовым инструкциям, попавшим на фото, и не считать произвольные надписи нарушением сами по себе. Нормализовал алиасы цены/прогноза для HTML/Markdown, чтобы значения модели не пропадали из карточек отчёта.

## 2026-10-19 — реализация по ТЗ, этапы 1–2 (в работе)

- Включён Docker Compose: Nginx, API Gateway, Auth, Listing, Search, Messaging, Notification, PostgreSQL, MongoDB, Redis и RabbitMQ. Внутренние сервисы не публикуют порты на хост.
- Добавлен API Gateway с проверкой access JWT, общим Redis rate limit, синхронной маршрутизацией Auth/Listing/Search и асинхронной публикацией `message.send` с ответом `202 Accepted`.
- Добавлены точные `/auth/*` endpoints, UUID внешней идентичности пользователя, bcrypt cost 12, refresh-сессии устройств, httpOnly refresh cookie, профиль и email-верификация через Redis-код с TTL 10 минут.
- Добавлена собственная async SMTP-отправка с Jinja2-шаблоном, Redis-лимитами 1 письмо в минуту и 5 в час, тремя попытками с задержкой и идемпотентностью по `correlation_id`. Проверка GitHub не выявила готового одного решения, покрывающего весь этот контракт; `fastapi-mail` покрывает отправку и шаблоны, но rate limit и идемпотентность здесь реализуются приложением.
- Сохранена прежняя таблица объявлений недвижимости и добавлена таблица UUID бизнес-объявлений с девятью группами полей, JSONB для составных данных и отдельными путями публичных файлов/конфиденциальных документов.
- Добавлены черновики, cursor pagination, загрузка файлов до 100 МБ с проверкой типа, минимум пять фотографий при отправке, статусная обработка документов и события `listing.creation.started` / `listing.on_moderation`.
- Добавлен PostgreSQL outbox с повторными попытками, чтобы события Listing не терялись при временной недоступности RabbitMQ.
- Разделены Docker volumes `public_uploads` и `private_uploads`; Nginx читает только публичный volume и отдаёт файлы с кэшированием на 30 дней.
- Убрана прямая геокодирующая HTTP-зависимость старых Listing-маршрутов, чтобы сервис не обращался к стороннему API.
- Добавлен Analytic Scripts: расчёт финансовых показателей, графиков и consistency checks по входному `listing.creation.started`; отчёт хранится в своей MongoDB и возвращается Listing событием.
- Search+Catalog индексирует только allow-list публичных данных из `listing.creation.completed`, поддерживает фильтры, сортировку и cursor pagination.
- Notification хранит события в своей MongoDB и доставляет их только через авторизованный in-app WebSocket; добавлен Rabbit consumer для объявлений, сообщений и событий Auth.
- Listing начал принимать analytics result events и агрегировать отчёты, соблюдая приоритет документов паспорта/ФНС/справки доходов над вердиктом AI.
- В Listing добавлена проверка ИНН ИП по контрольным цифрам ФНС и условный outbox-триггер `parsers.request.registry`; парсеры не запускаются для самозанятых, пустого ФИО или некорректного ИНН.

## 2026-10-25 — env, Parsers → Analytic AI → Listing

- Секреты вынесены в локальные `.env` по сервисам; в Git остаются только шаблоны `*.env.example`, реальные `.env` и ключи не индексируются.
- Listing публикует `parsers.request.registry` в exchange `parsers` (очередь `parsers.tasks`) и заранее объявляет `reply_to=ai.reply.<correlation_id>`; Parsers отвечает напрямую в эту очередь.
- Analytic AI при `registry_check=awaiting` параллельно запускает vision-проверку фото и ждёт ответ Parsers через `ai.reply.*` / таймаут `ai.resume`; итог публикуется как `listing.ai.analysis.completed`.
- Детерминированная сверка ИП: скачанный документ, совпадение ФИО/ИНН в тексте, статус ИП; при несовпадении — `requires_moderation`.
- Listing собирает отчёты Scripts + AI в `listing.results` и принимает финальное решение по объявлению.
- Интеграционный сценарий: `analytic-ai/tests/run_registry_then_ai.py` + фикстура `registry_then_ai.json` (тестовый ИНН/ФИО).
- Пакет `shared/` нужен: общие схемы, JWT/пароли и события для Auth, Listing и Messaging в Docker-сборке.
